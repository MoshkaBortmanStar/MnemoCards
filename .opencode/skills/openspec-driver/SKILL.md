# OpenSpec Change Driver — работа через движок

В этом проекте фичи проходят через жёсткий конвейер:
`MAIN.md → --new (proposal → spec-bdd → tasks) → --codegen (тесты → код)`.

Движок — скрипт `.agent/run-agent.py` в корне проекта. Он сам вызывает LLM
по своим промптам и пишет артефакты на диск. Твоя роль — оркестрация,
ревью и доводка, а НЕ ручная генерация артефактов.

## Шаг 0. Проверка движка

```bash
test -f .agent/run-agent.py && echo OK
```

- `OK` → работай по шагам ниже.
- Нет файла → скажи пользователю: движок не установлен, установка
  `cp -r <путь-к-creator>/.agent . && python3 .agent/run-agent.py --init`.
  Ручную генерацию артефактов начинай только с явного разрешения.

## Рабочий процесс

### Пользователь просит фичу («хочу...», «добавь...», «нужно...»)

1. Если фича неясна — сначала коротко уточни (1–3 вопроса, стиль
   brainstorming-скилла). НЕ начинай генерацию по сырой двусмысленной мысли.
2. Если `specs/MAIN.md` отсутствует — предложи сначала
   `--main "что за приложение"` (контекст для всех генераций).
3. Запусти конвейер:
   ```bash
   python3 .agent/run-agent.py --new "<уточнённый промпт>"
   ```
4. Прочитай созданный `specs/<change-id>/spec-bdd.md` и покажи пользователю
   краткое резюме сценариев (S1..Sn) — НЕ вываливай файл целиком.
5. Пользователь правит спеку (руками или через тебя) → при сильных правках:
   ```bash
   python3 .agent/run-agent.py --tasks --change <ID>   # перегенерить план
   ```

### Кодогенерация

```bash
python3 .agent/run-agent.py --codegen --change <ID> --dry-run   # посмотреть
python3 .agent/run-agent.py --codegen --change <ID>             # записать (спросит y/N)
```

После записи — прогони тесты (`mvn test` / аналог из стека). Если падают:
дожимай код сам в стиле TDD-скилла, спека уже описывает ожидаемое поведение.

## Шпаргалка команд

| Команда | Назначение |
|---|---|
| `--main "описание"` | создать/обновить мейн-спеку `specs/MAIN.md` |
| `--new "промпт"` | полный конвейер: proposal + spec-bdd + tasks |
| `--spec/--tasks/--proposal --change <ID>` | перегенерация одного артефакта |
| `--codegen --change <ID>` | код по спеке и таскам |
| `--list` / `--status [--change ID]` | список изменений / статусы |
| `--offline` | каркасы без LLM |
| `--model NAME` / `--profile work\|glm\|home` | выбор модели/провайдера разово |

`<ID>` можно сокращать: полный `change-002-...`, префикс `change-002` или номер `2`.

## Правила экономии токенов

- Вывод скрипта уже содержит всё нужное (пути артефактов) — не перечитывай
  файлы без необходимости.
- Читай `spec-bdd.md` только на ревью; `tasks.md` — перед кодогенерацией.
- НЕ копируй содержимое артефактов в ответ целиком — резюмируй.
- Сырой ответ кодогенерации лежит в `specs/<ID>/codegen-output.md` — не читай,
  если файлы записались успешно.

## Принципы

- Спека важнее кода: несоответствие кода спеке = чинить код (или спеку
  осознанно, с явного согласия пользователя).
- Код без спеки не пишем. Прежде чем кодить фичу — проверь, есть ли change-*;
  нет — предложи `--new`.
- Никогда не запускай `--codegen` без `--dry-run`-ревью файлов при первом
  использовании новой модели.
