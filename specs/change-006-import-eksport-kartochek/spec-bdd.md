# BDD Spec: Импорт и экспорт карточек колоды через CSV

> **Change ID:** `add-csv-import-export`
> **Дата:** 2026-09-16

Сводка: спецификация покрывает новую capability `deck.csv-transfer` — 25 сценариев: точка входа на экране колоды, экспорт (формат файла, кодировка, экранирование, краевые случаи), импорт (автодетект разделителя, необязательный заголовок, валидация строк, семантика добавления, итоги), общие ограничения (SAF, раунд-трип). Фича полностью офлайн: HTTP-эндпоинтов нет, поэтому классы ошибок выражены в терминах UI — аналог 400 (нечитаемый/некорректный файл: S18, S19), аналог 404 (устаревшая колода: S21), аналог 500 (ошибки ввода-вывода и БД: S8, S22). Предполагается существование экрана содержимого колоды (точка входа — список колод); сценарии оперируют действиями пользователя и состояниями экрана/Room.

## Контракт CSV-файла

- Кодировка: UTF-8 с BOM (первые байты `EF BB BF`).
- Разделитель записей: `CRLF` при экспорте (при импорте принимаются также `LF`).
- Разделитель колонок при экспорте — `,`. При импорте разделитель определяется автоматически: в первой строке файла подсчитывается количество `,` и `;`, побеждает символ, которого больше (при равенстве — запятая). Это нужно для файлов Excel в русской локали, где CSV сохраняется через `;`.
- Первая строка файла при экспорте — заголовок `front,back`. При импорте заголовок необязателен: первая строка пропускается, только если её колонки (после разделения найденным разделителем) равны `front` и `back` без учёта регистра; иначе она обрабатывается как обычная строка-карточка.
- Колонка 1 — лицевая сторона (слово), колонка 2 — перевод.
- Экранирование по RFC 4180: поле, содержащее `,`, `"` или перевод строки, заключается в `"`; символ `"` внутри поля удваивается.
- Файл содержит только текст карточек: идентификаторы и параметры SRS не выгружаются и не импортируются.

Правила импорта: BOM пропускается; разделитель определяется по первой строке (см. контракт выше); строка заголовка пропускается, только если её колонки — `front` и `back` без учёта регистра; строка пропускается, если лицевая сторона или перевод пусты (после обрезки пробелов); используются первые две колонки, лишние — игнорируются; все валидные строки добавляются как новые карточки без дедупликации; изменения применяются к Room атомарно.

## Сценарии

### S1: Экран колоды содержит действия «Экспорт» и «Импорт»

- **GIVEN** приложение запущено без сети, в Room есть колода с карточками, пользователь открыл экран содержимого колоды из списка колод
- **WHEN** экран содержимого колоды отображается
- **THEN** на экране видны действия «Экспорт» и «Импорт»; карточки и счётчик колоды читаются из Room через Flow

### S2: Экспорт — успешная выгрузка (happy path)

- **GIVEN** колода содержит 3 карточки: («cat», «кошка»), («dog», «собака»), («sun», «солнце»); открыт экран колоды
- **WHEN** пользователь нажимает «Экспорт», в системном диалоге CreateDocument (mime `text/csv`, предложенное имя — название колоды, например `Английский.csv`) подтверждает расположение
- **THEN** файл создан по выбранному Uri; содержимое — заголовок `front,back` и 3 строки данных с разделителем `,` в UTF-8 с BOM; показано подтверждение «Файл сохранён»; данные колоды в Room не изменились, счётчик карточек прежний

### S3: Экспорт — UTF-8 с BOM и кириллица

- **GIVEN** колода содержит карточку с кириллицей: «привет» → «hello»
- **WHEN** выполняется экспорт
- **THEN** первые байты файла — `EF BB BF`; текст «привет» закодирован в UTF-8 и при открытии файла в табличном редакторе читается корректно, без «кракозябр»

### S4: Экспорт — экранирование спецсимволов по RFC 4180

- **GIVEN** колода содержит карточки со значениями, включающими запятую («hello, world»), кавычку (say "hi") и перенос строки внутри текста
- **WHEN** выполняется экспорт
- **THEN** каждое значение с `,`, `"` или переводом строки обёрнуто в двойные кавычки, внутренние кавычки удвоены (например, `"say ""hi"""`); при обратном парсинге по RFC 4180 каждая строка даёт ровно 2 колонки с исходными текстами

### S5: Экспорт — только текст карточек, без SRS-данных

- **GIVEN** выполняется экспорт колоды, карточки которой имеют служебные поля (id, состояние повторений)
- **WHEN** файл сформирован
- **THEN** каждая строка данных содержит ровно две колонки — текст сторон; идентификаторы, интервалы, даты и другие параметры SRS в файл не попадают

### S6: Экспорт — пустая колода

- **GIVEN** колода существует, карточек в ней 0
- **WHEN** пользователь выполняет экспорт
- **THEN** создаётся файл из единственной строки-заголовка `front,back` (с BOM); ошибка не показывается, выводится подтверждение сохранения

### S7: Экспорт — отмена системного диалога

- **GIVEN** после нажатия «Экспорт» открыт системный диалог CreateDocument
- **WHEN** пользователь отменяет диалог
- **THEN** файл не создаётся, ошибка не показывается, экран колоды и Room остаются в прежнем состоянии

### S8: Экспорт — ошибка записи файла (аналог 500)

- **GIVEN** расположение в диалоге подтверждено, но запись в выбранный Uri завершается ошибкой ввода-вывода (например, хранилище недоступно)
- **WHEN** выполняется запись файла
- **THEN** показывается понятная ошибка «Не удалось сохранить файл»; приложение не падает; данные колоды не изменены, частично записанный файл не оставляется

### S9: Импорт — успешное добавление (happy path)

- **GIVEN** текущая колода содержит 5 карточек; выбран CSV-файл (экспорт другой колоды) с 4 валидными строками
- **WHEN** пользователь нажимает «Импорт» и выбирает файл в системном диалоге OpenDocument (mime `text/csv`)
- **THEN** в колоду добавляется 4 карточки, счётчик на экране обновляется автоматически (5 → 9); показывается итог «Добавлено: 4, пропущено: 0»; существующие 5 карточек не изменены и не удалены

### S10: Импорт — заголовок и BOM пропускаются (заголовок в любом регистре)

- **GIVEN** выбранный файл начинается с BOM и строки заголовка в верхнем регистре `FRONT,BACK`, за которой следуют строки данных
- **WHEN** выполняется импорт
- **THEN** строка заголовка не создаёт карточку и не попадает в итог (сравнение колонок без учёта регистра); BOM не приклеивается к тексту первой импортированной карточки

### S11: Импорт — файл без строки заголовка

- **GIVEN** выбранный файл не содержит строки заголовка: первая строка — «cat», «кошка», вторая — «dog», «собака»
- **WHEN** выполняется импорт
- **THEN** первая строка обрабатывается как обычная карточка, а не отбрасывается: добавлены 2 карточки («cat»/«кошка», «dog»/«собака»); итог «Добавлено: 2, пропущено: 0»

### S12: Импорт — пропуск строк с пустыми полями

- **GIVEN** файл содержит строки: валидную («cat», «кошка»); с пустой лицевой стороной («», «собака»); с пустым переводом («sun», «»); строку из одних пробелов
- **WHEN** выполняется импорт
- **THEN** добавлена 1 карточка «cat»/«кошка»; показан итог «Добавлено: 1, пропущено: 3»; в колоде не появляется карточек с пустой лицевой стороной или пустым переводом

### S13: Импорт — парсинг экранированных значений (RFC 4180)

- **GIVEN** файл содержит строку `"hello, world","скажи ""привет"""` и строку со значением, содержащим перенос строки внутри кавычек
- **WHEN** выполняется импорт
- **THEN** созданы карточки с точными исходными текстами: «hello, world» → «скажи "привет"» и значение с переносом строки — единое поле; запятая внутри кавычек не разбивает строку на лишние колонки

### S14: Импорт — разделитель точка с запятой (Excel, русская локаль)

- **GIVEN** выбранный файл сохранён Excel в русской локале с разделителем `;`: строки `front;back`, `cat;кошка`, `"hello, world";привет`
- **WHEN** выполняется импорт
- **THEN** разделитель определён автоматически по первой строке (`;` встречается чаще, чем `,`); заголовок пропущен; добавлены 2 карточки, включая «hello, world»/«привет» — запятая внутри кавычек не мешает парсингу; итог «Добавлено: 2, пропущено: 0»

### S15: Импорт — существующие карточки не затрагиваются, дубликаты добавляются как новые

- **GIVEN** колода уже содержит карточку «cat»/«кошка»; файл содержит строку «cat», «кошка»
- **WHEN** выполняется импорт
- **THEN** исходная карточка не изменена и не удалена; из файла создаётся отдельная новая карточка «cat»/«кошка» (дедупликация не выполняется — все валидные строки добавляются); итог «Добавлено: 1, пропущено: 0»

### S16: Импорт — карточки сразу готовы к повторению

- **GIVEN** импорт добавил N карточек в колоду
- **WHEN** пользователь запускает тренировку этой колоды
- **THEN** импортированные карточки входят в сессию повторения наравне с созданными вручную (те же правила отбора, что для новых карточек); отдельная активация не требуется

### S17: Импорт — строки с недостаточным и избыточным числом колонок

- **GIVEN** файл содержит строку из одной колонки («solo») и строку из трёх колонок («a», «b», «c»)
- **WHEN** выполняется импорт
- **THEN** строка «solo» пропущена (перевод пуст) и учтена в «пропущено»; из строки «a», «b», «c» взяты первые две колонки — добавлена карточка «a»/«b», лишние колонки игнорируются

### S18: Импорт — файл не CSV или нечитаемый (аналог 400)

- **GIVEN** выбранный файл — бинарный (например, изображение) либо текст в некорректной UTF-8 кодировке
- **WHEN** выполняется импорт
- **THEN** показывается понятная ошибка «Файл не является CSV или не читается»; не добавлена ни одна карточка; счётчик и содержимое колоды без изменений

### S19: Импорт — пустой файл (аналог 400)

- **GIVEN** выбранный файл имеет размер 0 байт
- **WHEN** выполняется импорт
- **THEN** показывается понятная ошибка (файл пуст или не является CSV); колода не меняется

### S20: Импорт — отмена системного диалога

- **GIVEN** после нажатия «Импорт» открыт системный диалог OpenDocument
- **WHEN** пользователь отменяет выбор файла
- **THEN** импорт не выполняется, состояние экрана и колоды без изменений, ошибка не показывается

### S21: Импорт — колода не найдена (аналог 404)

- **GIVEN** экран колоды открыт, но к моменту применения импорта данные экрана устарели: колода отсутствует в Room (например, удалена фоновой синхронизацией)
- **WHEN** разбор файла завершён и выполняется вставка карточек
- **THEN** показывается ошибка «Колода не найдена»; карточки не добавлены ни в одну колоду; приложение не падает

### S22: Импорт — ошибка БД при вставке (аналог 500)

- **GIVEN** вставка карточек в Room завершается ошибкой базы данных (например, диск недоступен)
- **WHEN** выполняется импорт
- **THEN** показывается понятная ошибка; изменения применяются атомарно — частичная вставка откачена, колода содержит только исходные карточки

### S23: Импорт — отзывчивость UI на большом файле

- **GIVEN** выбран CSV-файл с 1000 строк
- **WHEN** выполняется импорт
- **THEN** разбор и вставка выполняются вне UI-потока (Coroutines); экран остаётся отзывчивым, ANR не возникает; по завершении показан итог «Добавлено: N, пропущено: M»

### S24: Доступ к файлам только через SAF, без разрешений хранилища

- **GIVEN** чистая установка приложения, разрешения на хранилище не выданы
- **WHEN** пользователь выполняет экспорт (S2) и импорт (S9)
- **THEN** оба сценария завершаются успешно через системные диалоги CreateDocument / OpenDocument; запрос разрешений на хранилище не появляется; прямые пути к файлам не используются

### S25: Раунд-трип — экспорт из одной колоды и импорт в другую

- **GIVEN** колода A содержит карточки с кириллицей и спецсимволами; колода B пуста
- **WHEN** колода A экспортирована в CSV-файл, файл импортирован в колоду B
- **THEN** колода B содержит те же пары текстов, что и колода A; SRS-состояние не переносится — все карточки колоды B новые

## OpenAPI Delta

Изменений контракта API нет: фича полностью офлайн и не затрагивает сетевой слой (Retrofit/OkHttp). Новые эндпоинты и схемы не появляются; HTTP-коды 400/404/500 в рантайме не возникают — соответствующие краевые случаи реализованы как ошибки UI (аналог 400 — S18, S19; аналог 404 — S21; аналог 500 — S8, S22).

```yaml
# openapi-delta
paths: {}
components:
  schemas: {}
```
