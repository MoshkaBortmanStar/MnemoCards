# BDD Spec: Управление колодами

> **Change ID:** `add-deck-management`
> **Дата:** 2026-09-16

Сводка: спецификация покрывает capability `deck.management` — создание колод через форму с одним полем (S1–S5), контекстное меню по долгому нажатию с действиями «Переименовать»/«Удалить» (S6–S7), переименование (S8–S11), удаление с подтверждением и каскадным удалением карточек (S12–S15), пустое состояние списка (S16–S17), персистентность изменений в Room (S18–S20), а также краевые случаи: валидация пустого названия, равноправие базовой колоды, устаревший элемент (аналог 404) и ошибка БД (аналог 500). Изменение полностью локальное — сеть, HTTP-эндпоинты и OpenAPI-контракт не затрагиваются; сценарии описаны в терминах действий пользователя и состояний экрана.

## Сценарии

### S1: Создание — новая колода появляется в списке

- **GIVEN** Приложение запущено, стартовый экран «Список колод» показывает хотя бы одну колоду из Room
- **WHEN** Пользователь нажимает кнопку добавления колоды, вводит название «Английские глаголы» и подтверждает сохранение
- **THEN** Форма закрывается, колода «Английские глаголы» сразу появляется в списке со счётчиком «0 карточек», запись немедленно сохранена в Room (в таблице колод появилась новая строка)

### S2: Валидация — пустое название при создании отклоняется

- **GIVEN** Открыта форма создания колоды, поле названия пустое
- **WHEN** Пользователь нажимает кнопку сохранения
- **THEN** Показана ошибка валидации (например, «Название не может быть пустым»), форма остаётся открытой, колода не создана — в Room новая запись не появилась

### S3: Валидация — название только из пробелов отклоняется

- **GIVEN** Открыта форма создания колоды, поле содержит только пробелы (например, «   »)
- **WHEN** Пользователь нажимает кнопку сохранения
- **THEN** Ввод трактуется как пустой: показана ошибка валидации, колода не создаётся, в Room ничего не записано

### S4: Краевой случай — дубликат названия разрешён

- **GIVEN** В списке уже есть колода «Немецкий»
- **WHEN** Пользователь создаёт новую колоду с тем же названием «Немецкий»
- **THEN** Создание разрешено: в списке две колоды с одинаковым названием (уникальность имён не требуется), каждая ведёт независимый набор карточек

### S5: Краевой случай — очень длинное название сохраняется и обрезается при показе

- **GIVEN** Открыта форма создания колоды
- **WHEN** Пользователь вводит название длиной 100+ символов и сохраняет
- **THEN** Колода создаётся и хранится в Room с полным названием; в списке название отображается с обрезкой (ellipsis), полный текст доступен при открытии формы переименования

### S6: Долгое нажатие — меню с действиями «Переименовать» и «Удалить»

- **GIVEN** Список колод показывает хотя бы одну колоду
- **WHEN** Пользователь выполняет долгое нажатие (long press) на колоду
- **THEN** Открывается контекстное меню ровно с двумя действиями: «Переименовать» и «Удалить»

### S7: Долгое нажатие — закрытие меню без выбора ничего не меняет

- **GIVEN** Открыто контекстное меню колоды
- **WHEN** Пользователь закрывает меню (тап вне меню или системная кнопка «назад»)
- **THEN** Меню скрывается, список и Room остаются без изменений

### S8: Переименование — название обновляется в списке немедленно

- **GIVEN** В списке колода «Немецкий» со счётчиком N карточек; через контекстное меню выбрано «Переименовать», открыта форма с текущим названием в поле
- **WHEN** Пользователь вводит «Немецкий B1» и подтверждает сохранение
- **THEN** Список немедленно (без перезапуска экрана) показывает «Немецкий B1» вместо «Немецкий», счётчик карточек не изменился, в Room обновлена та же запись `DeckEntity` (новая строка не создаётся)

### S9: Валидация — пустое название при переименовании отклоняется

- **GIVEN** Открыта форма переименования, поле названия очищено
- **WHEN** Пользователь нажимает кнопку сохранения
- **THEN** Показана ошибка валидации «Название не может быть пустым», форма остаётся открытой, прежнее название колоды сохраняется и в списке, и в Room

### S10: Переименование — отмена оставляет прежнее название

- **GIVEN** Открыта форма переименования колоды «Немецкий», в поле введено «Немецкий B1»
- **WHEN** Пользователь нажимает «Отмена»
- **THEN** Форма закрыта, в списке колода по-прежнему называется «Немецкий», в Room изменений нет

### S11: Переименование — сохранение без изменений не вызывает ошибку

- **GIVEN** Открыта форма переименования, поле содержит текущее название без изменений
- **WHEN** Пользователь подтверждает сохранение
- **THEN** Операция завершается без ошибки и без изменений: видимый список и Room остаются в прежнем состоянии

### S12: Удаление — подтверждение удаляет колоду вместе со всеми карточками

- **GIVEN** В списке колоды «Английский» (3 карточки) и «Немецкий» (5 карточек); через меню колоды «Английский» выбрано «Удалить», показан диалог подтверждения
- **WHEN** Пользователь подтверждает удаление
- **THEN** Колода «Английский» и все 3 её карточки удалены из Room единой операцией (каскадно или в транзакции), в списке остаётся только «Немецкий» с 5 карточками, диалог закрыт, приложение не падает

### S13: Удаление — отмена подтверждения сохраняет колоду

- **GIVEN** Показан диалог подтверждения удаления колоды
- **WHEN** Пользователь отменяет действие (кнопка «Отмена» или тап вне диалога)
- **THEN** Диалог закрыт, колода и её карточки остаются в списке и в Room без изменений

### S14: Базовая колода — переименовывается как обычная

- **GIVEN** В списке присутствует базовая колода, засидированная при первом запуске (5 карточек)
- **WHEN** Пользователь выполняет долгое нажатие → «Переименовать» → вводит новое название → сохраняет
- **THEN** Базовая колода переименовывается без каких-либо специальных запретов: новое название сразу отображается в списке и записано в Room

### S15: Базовая колода — удаляется как обычная

- **GIVEN** В списке присутствует базовая колода с 5 карточками
- **WHEN** Пользователь выполняет долгое нажатие → «Удалить» → подтверждает удаление
- **THEN** Базовая колода и её 5 карточек удалены из Room; поведение идентично удалению обычной колоды, специальной защиты нет

### S16: Удаление последней колоды — пустое состояние с приглашением создать первую

- **GIVEN** В списке единственная колода (любая, включая базовую)
- **WHEN** Пользователь удаляет её с подтверждением
- **THEN** Список пуст: показано пустое состояние с сообщением («Пока нет колод») и кнопкой-приглашением создать первую колоду

### S17: Пустое состояние — кнопка приглашения открывает форму создания

- **GIVEN** Список колод пуст, показано пустое состояние
- **WHEN** Пользователь нажимает кнопку приглашения «Создать первую колоду»
- **THEN** Открывается форма создания; после сохранения непустого названия колода появляется в списке и пустое состояние исчезает; пустое название по-прежнему отклоняется (см. S2–S3)

### S18: Персистентность — все изменения переживают перезапуск

- **GIVEN** За одну сессию пользователь создал колоду «A», переименовал колоду «B» в «B2», удалил колоду «C»
- **WHEN** Приложение полностью закрывается и запускается снова
- **THEN** Список в точности соответствует состоянию на момент закрытия: колода «A» присутствует, колода «B2» присутствует под новым названием, колода «C» отсутствует, счётчики карточек совпадают

### S19: Краевой случай — удалённая базовая колода не возвращается после перезапуска

- **GIVEN** Пользователь удалил базовую колоду, записи о ней в Room больше нет
- **WHEN** Приложение перезапускается
- **THEN** Базовая колода не пересоздаётся сидингом (механизм сидинга не должен воскрешать удалённые данные); если после удаления в базе 0 колод — снова показано пустое состояние с приглашением, а не засиденный список

### S20: Краевой случай — новая колода с именем удалённой создаётся пустой

- **GIVEN** Ранее существовавшая колода «Немецкий» с 5 карточками была удалена
- **WHEN** Пользователь создаёт новую колоду с названием «Немецкий»
- **THEN** Новая колода создаётся со счётчиком «0 карточек»; карточки удалённой колоды не восстанавливаются и не прикрепляются к новой

### S21: Краевой случай (аналог 404) — колода-цель уже отсутствует в Room

- **GIVEN** Контекстное меню или диалог открыт для колоды, которая к моменту выполнения действия уже удалена из Room (устаревший элемент списка)
- **WHEN** Пользователь выполняет «Переименовать» или «Удалить» для этой колоды
- **THEN** Операция безопасно завершается как no-op: UI синхронизируется с актуальным состоянием Room (колода пропадает из списка), «призрачные» записи не создаются, приложение не падает

### S22: Краевой случай (аналог 500) — ошибка БД при записи

- **GIVEN** Имитирован сбой Room при записи (вставка, обновление или удаление выбрасывает исключение, например ошибка диска)
- **WHEN** Пользователь подтверждает создание, переименование или удаление колоды
- **THEN** Показано сообщение об ошибке, экран остаётся консистентным с фактическим состоянием Room (изменение не применено частично), приложение не падает
