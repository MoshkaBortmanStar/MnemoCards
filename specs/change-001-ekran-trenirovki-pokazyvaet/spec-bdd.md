# BDD Spec: Экран тренировки карточек

> **Change ID:** `add-review-screen`
> **Дата:** 2026-09-16

Сводка: спецификация покрывает первую реализацию capability `cards.review` на статических данных — полный пользовательский цикл сессии: старт, переворот карточки по тапу, оценка ответа одной из четырёх кнопок, переход к следующей карточке, завершение колоды экраном «на сегодня всё». Отдельно зафиксированы UI-краевые случаи: границы интеракций (тап вне карточки, повторный тап, double-tap), сохранение состояния при смене конфигурации, произвольная языковая пара и длинный текст. Фича полностью клиентская: сеть, хранилище и SRS-планирование отсутствуют, поэтому сетевые ошибки (400/404/500) и валидация входных данных неприменимы по построению — это зафиксировано в примечании после сценариев.

## Сценарии

### S1: Старт сессии — первая карточка лицевой стороной

- **GIVEN** приложение запущено, в коде захардкожена колода из 5 карточек (упорядоченный список пар «слово — перевод»), экран тренировки открывается впервые
- **WHEN** пользователь открывает экран тренировки
- **THEN** отображается карточка №1 из 5 в состоянии «лицевая сторона»: видно слово первой пары; перевод скрыт; кнопки оценки («Забыл», «Трудно», «Хорошо», «Легко») не отображаются

### S2: Переворот карточки по тапу

- **GIVEN** экран тренировки показывает лицевую сторону карточки №1 (слово, перевод скрыт)
- **WHEN** пользователь выполняет одиночный тап по области карточки
- **THEN** карточка переворачивается и показывает обратную сторону — перевод; под карточкой появляются четыре активные кнопки оценки: «Забыл», «Трудно», «Хорошо», «Легко»

### S3: Краевой — тап вне области карточки

- **GIVEN** экран тренировки показывает неперевёрнутую карточку (лицевая сторона)
- **WHEN** пользователь выполняет тап по экрану вне границ карточки
- **THEN** состояние экрана не меняется: карточка остаётся лицевой стороной, перевод не показывается; переворот выполняется только тапом по самой карточке

### S4: Краевой — повторный тап по перевёрнутой карточке

- **GIVEN** карточка перевёрнута: показан перевод и четыре кнопки оценки
- **WHEN** пользователь повторно тапает по карточке
- **THEN** состояние экрана не меняется: карточка остаётся перевёрнутой, кнопки оценки остаются на экране; обратный переворот и пропуск карточки по тапу не выполняются — к следующей карточке ведёт только нажатие кнопки оценки

### S5: Оценка «Хорошо» — переход к следующей карточке

- **GIVEN** карточка №1 перевёрнута, кнопки оценки активны
- **WHEN** пользователь нажимает кнопку «Хорошо»
- **THEN** отображается карточка №2 в исходном состоянии: лицевая сторона (слово), перевод скрыт, кнопки оценки скрыты до переворота

### S6: Краевой — все четыре оценки эквивалентны (SRS-эффект отсутствует)

- **GIVEN** показана перевёрнутая i-я карточка (i < 5)
- **WHEN** пользователь нажимает любую из кнопок — «Забыл», «Трудно», «Хорошо» или «Легко»
- **THEN** независимо от нажатой кнопки отображается следующая (i+1)-я карточка лицевой стороной; порядок карточек фиксирован захардкоженным списком и не меняется; интервалы повторения не пересчитываются (SRS-планирование вне скоупа фичи)

### S7: Завершение колоды — экран «на сегодня всё»

- **GIVEN** в сессии последовательно пройдены 4 из 5 карточек (каждая оценена одной из кнопок), показана лицевая сторона карточки №5
- **WHEN** пользователь переворачивает карточку №5 и нажимает любую кнопку оценки
- **THEN** открывается экран «на сегодня всё»: карточки, слова, перевода и кнопок оценки на экране нет; отображается сообщение о завершении сессии

### S8: Краевой — экран «на сегодня всё» терминален для сессии

- **GIVEN** сессия завершена, показан экран «на сегодня всё»
- **WHEN** пользователь выполняет произвольные тапы по экрану
- **THEN** экран остаётся в состоянии «на сегодня всё»: новая сессия не стартует автоматически, карточка №1 и кнопки оценки не появляются (перезапуск сессии в скоуп данной фичи не входит)

### S9: Краевой — смена конфигурации (поворот экрана) сохраняет состояние сессии

- **GIVEN** идёт сессия, показана перевёрнутая карточка №3 (перевод и кнопки оценки на экране)
- **WHEN** происходит смена конфигурации устройства (поворот экрана) и экран пересоздаётся
- **THEN** после пересоздания отображается та же карточка №3 в перевёрнутом состоянии с кнопками оценки; прогресс сессии не сбрасывается, показ карточки №1 с начала не происходит

### S10: Краевой — произвольная языковая пара (разные письменности)

- **GIVEN** в захардкоженной колоде есть карточки, где слово и перевод используют разные письменности (латиница, кириллица, CJK-символы); конкретная языковая пара в коде не зашита
- **WHEN** такие карточки показываются в ходе сессии (лицевая и обратная стороны)
- **THEN** текст обеих сторон отображается «как есть», без транслитерации, обрезки и трансформации; переворот и оценка работают одинаково для всех карточек независимо от языка

### S11: Краевой — длинный текст карточки

- **GIVEN** в колоде есть карточка, у которой слово или перевод длиннее ширины области карточки
- **WHEN** эта карточка отображается (лицевая и перевёрнутая стороны)
- **THEN** текст переносится по словам либо обрезается с индикатором (многоточием) без выхода за границы карточки; вёрстка экрана не ломается, все четыре кнопки оценки полностью видимы и кликабельны

### S12: Краевой — двойное нажатие кнопки оценки (double-tap)

- **GIVEN** карточка №i перевёрнута, кнопки оценки активны
- **WHEN** пользователь дважды быстро нажимает одну и ту же кнопку оценки
- **THEN** обрабатывается только первое нажатие: выполняется ровно один переход к карточке №i+1; карточка №i+2 автоматически не показывается, сессия не пропускает карточку

> **Примечание о неприменимых HTTP-краевых случаях (400/404/500, валидация входа):** фича реализуется целиком на клиенте (Jetpack Compose) на захардкоженных данных — HTTP-запросы, эндпоинты и внешние хранилища в ней отсутствуют, поэтому сетевые ошибки и валидация входных данных неприменимы по построению. Эквивалентные классы рисков покрыты UI-сценариями: некорректные взаимодействия пользователя — S3, S4, S12; потеря состояния — S9; нестандартные данные для отображения — S10, S11.
