# BDD Spec: Настройки синхронизации и вход на сервер

> **Change ID:** `add-sync-settings`
> **Дата:** 2026-09-16

Сводка: спецификация покрывает экран настроек синхронизации — открытие со списка колод, валидацию полей, проверку соединения (успех, недоступность адреса, сертификат, 404, 500), вход (успех, 400, 401, 500, сетевые сбои), зашифрованное хранение токенов в Android Keystore, отказ от хранения пароля, сохранение адреса сервера между перезапусками, выход и переключение флага синхронизации с режимом мягкого/физического удаления, инварианты offline-first и структуры проекта. Формат запросов, ответов и коды ошибок — из specs/API.md и specs/openapi.yaml (источник истины); сетевые DTO генерируются из openapi.yaml плагином, тем же, что на сервере.

## Сценарии

### S1: Открытие экрана настроек со списка колод

- **GIVEN** приложение запущено, пользователь находится на экране списка колод, сервер синхронизации не настроен (состояние по умолчанию)
- **WHEN** пользователь открывает экран настроек синхронизации
- **THEN** экран открывается как маршрут существующего `MnemoCardsNavHost` (второй навигационный граф не создаётся); на экране присутствуют поля «Адрес сервера», «Логин», «Пароль», кнопки «Проверить соединение» и «Войти», индикатор состояния «Не подключено»; экран оформлен в `MnemoCardsTheme` (тёмная тема)

### S2: Без настроенного сервера приложение работает как раньше

- **GIVEN** сервер не настроен: адрес не введён, токенов нет, флаг синхронизации выключен; в Room есть колоды и карточки
- **WHEN** пользователь просматривает список колод, запускает тренировку, проходит сессию, выполняет импорт и экспорт
- **THEN** все функции работают как до изменения; сетевые вызовы не выполняются; удаления записей выполняются физически; ошибок сети не возникает

### S3: Краевой случай — валидация адреса сервера

- **GIVEN** экран настроек открыт, поле «Адрес сервера» пустое или содержит значение, не являющееся корректным URL (например, «sync example»)
- **WHEN** пользователь нажимает «Проверить соединение» или «Войти»
- **THEN** сетевой запрос не отправляется; под полем показана понятная ошибка валидации («Введите адрес сервера» / «Некорректный адрес»); состояние подключения не меняется

### S4: Краевой случай — валидация логина и пароля

- **GIVEN** введён корректный адрес сервера, поле «Логин» или «Пароль» пустое
- **WHEN** пользователь нажимает «Войти»
- **THEN** запрос не отправляется; показана инлайн-ошибка «Заполните логин и пароль»; состояние остаётся «Не подключено»

### S5: Проверка соединения — сервер отвечает

- **GIVEN** в поле «Адрес сервера» введено `https://sync.example.com`, сервер доступен
- **WHEN** пользователь нажимает «Проверить соединение»; клиент выполняет GET-запрос к эндпоинту доступности (`GET /api/v1/health` согласно specs/API.md)
- **THEN** статус ответа 200; на экране сообщение «Сервер отвечает»; состояние подключения не меняется — вход не выполняется, токены не запрашиваются

### S6: Проверка соединения — адрес недоступен

- **GIVEN** введён `https://sync.example.com`, домен не резолвится или соединение не устанавливается (OkHttp: `UnknownHostException`, таймаут соединения)
- **WHEN** пользователь нажимает «Проверить соединение»
- **THEN** показано сообщение «Адрес недоступен»; приложение не падает; ошибка сети не покидает экран настроек

### S7: Проверка соединения — сертификат не принят

- **GIVEN** сервер отвечает по HTTPS с сертификатом, не принимаемым системой (самоподписанный, просроченный); OkHttp бросает `SSLHandshakeException`
- **WHEN** пользователь нажимает «Проверить соединение»
- **THEN** показано сообщение «Сертификат не принят»; приложение не падает; запрос в обход проверки сертификата не выполняется

### S8: Краевой случай — проверка соединения вернула 404

- **GIVEN** по введённому адресу отвечает HTTP-сервер, но эндпоинт доступности отсутствует (адрес не является сервером MnemoCards); тестовый сервер (MockWebServer) возвращает 404
- **WHEN** пользователь нажимает «Проверить соединение»
- **THEN** статус 404 обработан согласно specs/API.md; показано сообщение «По этому адресу нет сервера синхронизации»; приложение не падает; состояние не меняется

### S9: Краевой случай — проверка соединения вернула 500

- **GIVEN** эндпоинт доступности отвечает 500 (или любым другим 5xx)
- **WHEN** пользователь нажимает «Проверить соединение»
- **THEN** показано понятное сообщение об ошибке сервера; приложение не падает; состояние подключения не меняется

### S10: Вход — успех

- **GIVEN** введены адрес `https://sync.example.com`, логин и пароль; учётные данные верны
- **WHEN** пользователь нажимает «Войти»; клиент отправляет POST-запрос входа (`POST /api/v1/auth/login` с логином и паролем в формате specs/openapi.yaml)
- **THEN** статус ответа 200, в теле access- и refresh-токены; токены сохранены в зашифрованном виде ключом из Android Keystore; пароль не сохраняется нигде; экран показывает состояние «Подключено» и адрес сервера; флаг синхронизации включён — удаления записей переходят в мягкий режим

### S11: Краевой случай — вход вернул 401 (неверные учётные данные)

- **GIVEN** введён верный адрес и неверный пароль; сервер отвечает 401 согласно specs/API.md
- **WHEN** пользователь нажимает «Войти»
- **THEN** показана причина — «Неверный логин или пароль»; токены не сохраняются; состояние остаётся «Не подключено»; флаг синхронизации остаётся выключенным

### S12: Краевой случай — вход вернул 400

- **GIVEN** сервер отвечает 400 на тело запроса (невалидный формат по контракту)
- **WHEN** пользователь нажимает «Войти»
- **THEN** причина ошибки из тела ответа показана понятным текстом; токены не сохраняются; приложение не падает

### S13: Краевой случай — вход вернул 500

- **GIVEN** `POST /api/v1/auth/login` отвечает 500
- **WHEN** пользователь нажимает «Войти»
- **THEN** показано сообщение об ошибке сервера; токены не сохраняются; состояние «Не подключено»; приложение не падает

### S14: Вход — сетевая ошибка во время запроса

- **GIVEN** введены корректные данные, но после нажатия соединение обрывается (`IOException`)
- **WHEN** выполняется запрос входа
- **THEN** показана причина сбоя («Адрес недоступен»); токены не сохранены; кнопки возвращаются в активное состояние; повторная попытка доступна

### S15: Защита от повторных нажатий

- **GIVEN** запрос «Проверить соединение» или «Войти» выполняется, кнопка в состоянии загрузки
- **WHEN** пользователь повторно нажимает ту же или другую кнопку
- **THEN** дублирующий сетевой запрос не отправляется; после завершения запроса UI консистентен

### S16: Токены хранятся только зашифрованными, пароль не хранится

- **GIVEN** выполнен успешный вход
- **WHEN** проверяется постоянное хранилище приложения (DataStore / SharedPreferences / Room)
- **THEN** токены присутствуют только в зашифрованном виде (ключ из Android Keystore); открытый текст токенов не встречается нигде; пароль отсутствует полностью

### S17: Перезапуск приложения — адрес и состояние переживают рестарт

- **GIVEN** выполнен успешный вход, приложение перезапущено, экран настроек открыт повторно
- **WHEN** проверяется состояние экрана
- **THEN** поле «Адрес сервера» заполнено сохранённым значением; состояние «Подключено» восстановлено из сохранённых токенов; поле «Пароль» пусто

### S18: Выход

- **GIVEN** состояние «Подключено»
- **WHEN** пользователь нажимает «Выйти»
- **THEN** токены удаляются из хранилища; экран переходит в состояние «Не подключено» (адрес сервера сохраняется); флаг синхронизации выключается — удаления записей возвращаются к физическому режиму

### S19: Мягкое удаление при включённой синхронизации

- **GIVEN** пользователь подключён, флаг синхронизации включён
- **WHEN** удаляется колода или карточка
- **THEN** запись помечается удалённой и остаётся в Room (мягкое удаление); физического удаления не происходит

### S20: Физическое удаление при выключенной синхронизации

- **GIVEN** пользователь не подключён (состояние по умолчанию или после выхода), флаг синхронизации выключен
- **WHEN** удаляется колода или карточка
- **THEN** запись физически удаляется из Room

### S21: Недоступность сервера не мешает заучиванию

- **GIVEN** пользователь подключён, но сервер недоступен (авиарежим, ошибка сети)
- **WHEN** пользователь просматривает колоды, проходит тренировку, выполняет импорт и экспорт
- **THEN** все функции работают из Room; сообщения об ошибках сети не появляются нигде, кроме экрана настроек; фоновая синхронизация данных не запускается (не входит в эту фичу)

### S22: Сетевые модели — только сгенерированные DTO

- **GIVEN** specs/openapi.yaml зафиксирован
- **WHEN** выполняется сборка проекта
- **THEN** модели запросов и ответов доступности и входа — DTO, сгенерированные из openapi.yaml тем же плагином, что используется на сервере; ручных сетевых моделей в коде клиента нет; изменение контракта применяется регенерацией, а не правкой вручную

### S23: Смена конфигурации экрана

- **GIVEN** экран настроек открыт, поля заполнены, отображается результат проверки или выполняется запрос
- **WHEN** пользователь поворачивает устройство (смена конфигурации)
- **THEN** введённые значения и состояние экрана сохраняются (состоянием владеет ViewModel через StateFlow); выполняющийся запрос не дублируется

### S24: Инварианты структуры и оформления

- **GIVEN** изменение реализовано, проект собирается
- **WHEN** проверяется структура кода
- **THEN** экран и ViewModel находятся в `com.mnemocards.ui.syncsettings`; сетевой API и хранилище токенов — в `com.mnemocards.data`; Room-сущности не покидают пакет `data`; новых пакетов верхнего уровня и второго NavHost нет; экран использует `MnemoCardsTheme` и токены `MaterialTheme.colorScheme` без прямых `Color(0xFF...)`

### S25: Краевой случай — адрес сервера с протоколом http

- **GIVEN** в поле «Адрес сервера» введён адрес с протоколом http (например, `http://sync.example.com`); Android по умолчанию блокирует незашифрованный трафик (cleartext traffic не разрешён)
- **WHEN** пользователь нажимает «Проверить соединение» или «Войти»
- **THEN** молчаливого сбоя запроса не происходит: валидация отклоняет адрес до отправки — инлайн-ошибка под полем «Незашифрованное соединение (http) заблокировано Android — используйте https-адрес»; пользователь понимает причину; сетевой запрос не отправляется; состояние подключения не меняется; разрешение cleartext-трафика в манифесте (usesCleartextTraffic / network security config) не включается

## OpenAPI Delta

Изменения контракта API относительно текущего состояния проекта:

```yaml
# openapi-delta
# Контракт фиксирован specs/API.md и specs/openapi.yaml — источник истины,
# собственный формат не придумывается. Изменение клиентское: существующие
# пути потребляются как есть, новые пути не добавляются, существующие
# схемы не изменяются. DTO генерируются из specs/openapi.yaml.
#
# Задействованные пути (без изменений):
#   GET  /api/v1/health      — проверка доступности сервера
#   POST /api/v1/auth/login  — вход, выдача access/refresh токенов
paths: {}
components:
  schemas: {}
```
