# BDD Spec: Локальное хранилище и список колод

> **Change ID:** `add-offline-storage`
> **Дата:** 2026-09-16

Сводка: спецификация покрывает инициализацию Room-хранилища (сидинг базовой колоды при первом запуске), сохранность данных между перезапусками, стартовый экран со списком колод (название + количество карточек), навигацию «список → тренировка колоды → назад», чтение карточек сессией `cards.review` из БД, а также краевые случаи в терминах состояний экрана. Фича полностью офлайнная: HTTP-эндпоинты, коды 400/404/500 и OpenAPI-контракт не появляются; их роль покрыта UI-состояниями (пустой список — S7, устаревший элемент — аналог 404 в S8, ошибка БД — аналог 500 в S9).

## Сценарии

### S1: Первый запуск — автоматическое создание базовой колоды

- **GIVEN** приложение установлено и запускается впервые, локальная база Room пуста (файл БД отсутствует)
- **WHEN** пользователь открывает приложение
- **THEN** в БД автоматически создаётся базовая колода с 5 карточками (те же пять пар «слово + перевод», что были в захардкоженной версии `cards.review`); стартовый экран показывает ровно одну колоду: её название и счётчик карточек «5»

### S2: Повторный запуск — данные переживают перезапуск, повторный сидинг не выполняется

- **GIVEN** приложение запускалось ранее, в БД уже есть базовая колода из 5 карточек, процесс приложения завершён системой или пользователем
- **WHEN** пользователь снова открывает приложение
- **THEN** стартовый экран показывает ту же колоду с теми же 5 карточками; дубликат базовой колоды не создаётся, карточки не плодятся

### S3: Стартовый экран — список колод с названием и количеством карточек

- **GIVEN** в БД Room хранится одна или несколько колод с разным количеством карточек
- **WHEN** пользователь находится на стартовом экране приложения
- **THEN** для каждой колоды отображается элемент списка: название колоды и число карточек в ней; список строится из данных Room через Flow и отражает актуальное состояние БД

### S4: Тап по колоде открывает тренировку этой колоды

- **GIVEN** на стартовом экране отображается список колод
- **WHEN** пользователь тапает по колоде
- **THEN** открывается экран тренировки (`cards.review`) для выбранной колоды: показана лицевая сторона (слово) первой карточки именно этой колоды

### S5: Сессия повторения читает карточки из Room

- **GIVEN** пользователь открыл тренировку колоды, у которой в БД 5 карточек
- **WHEN** сессия повторения стартует и выполняется (переворот, оценки, переходы)
- **THEN** все карточки сессии загружаются из Room по идентификатору выбранной колоды (захардкоженные данные больше не используются); в сессии участвуют только карточки выбранной колоды

### S6: Кнопка «назад» возвращает к списку колод

- **GIVEN** пользователь находится на экране тренировки колоды (в том числе на терминальном экране «на сегодня всё»)
- **WHEN** пользователь нажимает системную кнопку «назад» или кнопку «назад» на экране
- **THEN** выполняется возврат на экран списка колод; список отображает те же колоды и счётчики, что и до перехода

### S7: Краевой случай — пустой список колод (защитное пустое состояние)

- **GIVEN** БД инициализирована, но не содержит ни одной колоды (защитный сценарий: сидинг по какой-то причине не выполнился)
- **WHEN** пользователь открывает стартовый экран
- **THEN** отображается пустое состояние (заглушка вида «пока нет колод»); приложение не крашится и не показывает неинформативный пустой экран

### S8: Краевой случай — тап по колоде, отсутствующей в БД (аналог 404)

- **GIVEN** на экране списка отображается элемент колоды, данные которой к моменту тапа уже отсутствуют в БД (устаревшее состояние списка)
- **WHEN** пользователь тапает по этому элементу
- **THEN** экран тренировки не открывается на пустом наборе карточек; пользователь остаётся на списке, список перечитывается из Room и приводится к актуальному состоянию; крах приложения исключён

### S9: Краевой случай — ошибка инициализации или чтения БД (аналог 500)

- **GIVEN** при открытии базы Room возникает исключение (повреждён файл БД, ошибка миграции схемы)
- **WHEN** пользователь открывает приложение
- **THEN** приложение не падает; стартовый экран переходит в состояние ошибки с понятным сообщением и возможностью повторить загрузку; пустые или частичные данные не выдаются за валидные

### S10: Краевой случай — полное отсутствие сети не влияет на работу

- **GIVEN** на устройстве включён авиарежим (сеть полностью недоступна)
- **WHEN** пользователь выполняет любые сценарии фичи: просмотр списка, тренировка колоды, перезапуск приложения
- **THEN** поведение идентично работе при наличии сети; сетевые вызовы не выполняются, никаких сообщений о сети не показывается

### S11: Краевой случай — смена конфигурации и пересоздание Activity

- **GIVEN** пользователь находится на стартовом экране со списком колод
- **WHEN** происходит поворот экрана, смена темы или иное пересоздание Activity
- **THEN** список колод отображается корректно без повторного сидинга и без потери данных; данные перечитываются из Room

### S12: Консистентность счётчика карточек после сессии

- **GIVEN** пользователь полностью завершил сессию повторения колоды из 5 карточек, оценив каждый ответ
- **WHEN** пользователь возвращается на экран списка колод
- **THEN** счётчик карточек этой колоды по-прежнему равен 5 (оценки ответов в этой фиче не добавляют и не удаляют карточки); отображаемое количество соответствует данным БД
